  - Tokenize capsule: `flex:1` → natural content width at all viewports + visible seam between halves (fixes M-5/F-12 and V-6, same component).
  - Mobile header context: active-tab label in the space reclaimed by the capsule fix.
  - Viewport ownership ≤839px: overlay/panel sizing tracks the dynamic viewport (`100dvh`/`visualViewport` — mechanism decided in SPECIFY/DESIGN); suppress the orbital word badge while the panel is open, restore on close.
  - 600–839px band: resolve to one chrome model (conservative lean — fullscreen phone chrome ≤839px per M-13's simplest option; the alternative card model is a recorded DESIGN decision, not silent drift).
  - Sheet affordances: Card Creator gets a `MobileSheet` peek header (component slot exists); `BottomSheet` grabber becomes real drag-to-dismiss or is removed (conservative lean — `hideDragHandle` per M-12's smallest fix); close ≥44px via the item-30 floor; bottom padding/scroll-fade so the last row is never sliced.
  - Vocabulary filter row at 320px: horizontal-scroll chips or collapsed overflow so no control clips.

  - Selected-state recipe convergence, panel shadow/border, surface/alpha washes, empty-state centering, serif headings and the remaining V-* batch → item 33 `up-visual-system-convergence`.
  - Hit-target binding mechanics (the 44px floor itself: MobileSheet handle height, Toggle, inputs) → item 30 `up-a11y-hit-targets`; this item *consumes* that floor for sheet close/grabber rather than re-deriving it.
  - Scrollport bottom inset above the nav (M-3), tab mounting/scroll contract (F-1/F-5/F-19) → item 28 `up-tab-layout-contract`.

## Workflow

A learner on a phone opens the Universal Panel from the floating word badge. The system presents a fullscreen surface that owns the viewport edge to edge — nothing of the host page shows through, and the badge itself steps aside while the panel is open. The header now tells them where they are: the active tab's name beside a compact two-half tokenize capsule and the close control. When they want another surface, the bottom bar offers at most five clearly labelled destinations; the two they use least wait inside the Tools sheet, one tap away, listed as labelled rows. In the Dictionary tab, the collapsed Card Creator announces itself by name in a peek header instead of lurking as an anonymous pill — one tap or drag opens it. When they open the Tools sheet, it behaves like a sheet: an honest grabber or none, a close button they can actually hit, and no content sliced at the bottom edge. On a tablet-width window (600–839px) the same coherent mobile chrome applies rather than a card-on-page hybrid; at 320px even the vocabulary filter row fits without clipped controls. System↔system interactions: panel-open state suppresses/restores the orbital badge host; the sheet/demoted-tab registry feeds the Tools sheet; viewport size changes (browser chrome show/hide, rotation) reflow the frame without layout jumps in content.

## Journey

### AS-IS

1. A learner on a 390×844 phone taps the floating badge to open the panel — the surface fills the screen, but a ~10px strip of host-page chrome still shows beneath the bottom nav and the badge itself floats on top of the panel's right edge, so the "modal" never truly owns the screen (`panel.rect` 380×834 — audit-captured measurement, `audit.md:45` M-2; badge z-index above panel at all viewports, `tokens.json:544-546`).
2. They try to navigate: seven items at 51px each (audit-captured measurement, `audit.md:36`) render "Dicti… / Voca… / Studi… / Clips / Reca… / Setti… / Tools" — labels clipped mid-word at 390px, collapsing to "Dict/Voc/Stu/Clip" fragments at 320px, and dropping to 10px type — below the system's own 12px floor — under 360px.
3. They can't confirm where they landed: the active tab is a blue tint only, and the header shows a stretched pill with two icons floating in empty halves plus an X — no title, no context.
4. On the Dictionary tab they never discover the Card Creator — its collapsed sheet is a bare ~180px gray pill (`audit.md:46`) above the nav, indistinguishable from chrome decoration, and the peek-header slot the component already offers goes unused.
5. They open Tools to escape — the grabber is a decorative bar that can't be dragged, the close button is ~32px, and the last row is sliced off at the sheet's bottom edge.
6. The same user on a 768×1024 tablet gets the phone bottom nav and icon chrome inside a 94% rounded desktop card with page peeking at all four edges — neither mental model resolved — and on the Vocabulary tab at 320px the sort dropdown's chevron is clipped mid-glyph.

### TO-BE

1. The phone user taps the badge; the panel covers the dynamic viewport edge to edge — no page chrome shows at any side, and the badge is suppressed until the panel closes and then returns.
2. The bottom bar shows ≤5 destinations with complete labels in the user's locale at a legible size; the active one carries a positional indicator, and the header names the current tab in the space the shrunken capsule freed.
3. The tokenize control reads as one compact segmented capsule with a visible seam — same at 390px and 1440px — instead of two icons lost in a stretched pill.
4. On Dictionary, "Card Creator" peeks by name above the nav with a real affordance; a tap or drag opens it — the flagship feature is discoverable.
5. Opening Tools presents the demoted destinations as labelled rows two taps from anywhere; the sheet has an honest grabber (or none) and a ≥44px close, and scrollable content ends cleanly — no mid-row clipping.
6. At 768px the same resolved chrome model applies — fullscreen phone chrome or a true card, one model per band — and at 320px the vocabulary filter row keeps every control intact.

## Stories

- S1: As a phone user, I want the bottom navigation to show a small set of fully labelled destinations, so that I can read and tap the right one without guessing at clipped fragments — done when ≤5 destinations render complete labels at every width ≤839px in every shipped locale, and the demoted tabs are reachable through the Tools sheet in ≤2 taps.
- S2: As a mobile user, I want to see which surface I'm on without decoding a color tint, so that I never lose orientation — done when the active destination has a positional indicator and the header names the active tab.
- S3: As a mobile user, I want the open panel to be the only thing on screen, so that page chrome and floating widgets don't compete with it — done when no host-page pixels are visible at any viewport edge ≤839px (verified under browser-chrome show/hide) and the floating badge does not render above the open panel.
- S4: As a learner, I want the collapsed Card Creator to tell me what it is, so that I can find and open it — done when the collapsed sheet shows a named peek affordance.
- S5: As a user on a 600–839px device, I want one coherent chrome model, so that the panel doesn't feel like a bug — done when the band renders a single resolved model (no phone-nav-in-rounded-card hybrid) and the choice is recorded.
- S6: As a sheet user, I want sheet chrome to behave the way it looks, so that I can dismiss it predictably — done when the grabber is draggable or absent, the close target meets the 44px floor, and content never clips at the bottom edge.
- S7: As a 320px user, I want the vocabulary filter controls to fit, so that nothing I need is clipped away — done when the row scrolls or collapses rather than slicing a control.
- S8: As any user, I want the tokenize control to look like one control, so that its two halves read as a unit — done when the capsule hugs its content with a visible seam at all viewports.

## Decision

go — every claim is measured evidence (computed styles, screenshots, line-cited code), the fix is consolidation and reuse of affordances that already exist (Tools sheet rows, MobileSheet `header` slot, NavItem pill, badge `hide()`, `hideDragHandle`) rather than new machinery, and mobile legibility/orientation is a P1-class failure on the persona's primary device class. Sequencing after items 28/30 is declared and recorded, not blocking the intent.
