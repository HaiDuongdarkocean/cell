## Workflow

Narrative: an end user opens the universal panel over a video and moves between tabs — Dictionary to look up a word and build a card, Vocabulary to filter and triage marks, Study Modes to pick a preset, Settings to tune sync and appearance. At each step the user reads states off the surface: which item is selected, which control is clickable, which action is primary versus destructive versus off. In the converged panel, those readings come from one grammar — list selections glow `primary-subtle`, selected cards carry the inset ring, every dropdown is an opaque `Menu`, every footer has one primary action, groups are separated by hairlines, and muted always means disabled, never "secondary". The maintainer's parallel workflow: after items 28–32 land, this item sweeps subsystem by subsystem (chrome → tab surfaces → shared molecules), each stage a reviewable commit with before/after screenshot evidence per AGENTS.md. Start: user opens the panel. End: user operates any tab without re-learning the state language. Person↔device throughout; system↔system only where the shadow-DOM mount meets page backgrounds (V-9, V-21).

## Journey

### AS-IS

1. User opens the panel over a dark video page; the panel floats on the weakest shadow in the system (`--shadow-sm`) with a transparent border — its edge is visible only because this page happens to be darker (`20261006-universal-panel-ux-audit.md:42`; `tokens.css:524`).
2. In Dictionary, the user picks a deck from a `Select` whose listbox lets card copy bleed through the rows (V-2), hits a card-creator footer where `Clear`/`Add`/`Update` wear three different emphasis styles and `Update` reads disabled (`CardCreatorDialogContent.tsx:292-317`), and sees the same AnkiConnect failure twice — once as a banner, once as an inline row (V-7).
3. In Vocabulary, filter/sort controls read as bare underlined text links (V-5), the empty tab shows a lone unadorned line while sibling tabs get icon+title+CTA (V-11), and the status pill is a third chip implementation whose hover dims where the recap's brightens (F-13).
4. In Settings, section headers shout in a small-caps dialect outside the type system (V-4), `Sync now` sits in the footer styled like a disabled control (`SyncPanel.tsx:257-258`), slider tracks are nearly invisible (V-18), and hint ⓘ buttons wear a focus-ring-looking hover (V-15).
5. In the sidebar, the tab group and tool group are split by a ~64px void with no divider (V-10); collapsing the rail turns the header into a ~17-icon strip (V-16); and across all tabs "selected" has meant accent-bar, underline, ring, or solid fill depending on where the user looked (V-3).
6. Edge case: on a *bright* page the borderless low-shadow panel edge may disappear entirely (V-9 `20261006-universal-panel-ux-audit.md:42`; risk note: ephemeral `state/03-visual-desktop.md:77`), and muted-styled enabled actions get skipped as "unavailable" (V-17).

### TO-BE

1. User opens the panel on any page; it sits unmistakably above the content — `shadow-modal` plus a real border — and every dropdown/listbox that opens inside it is opaque `surface-elevated`/`field-solid`, readable over anything underneath (N2).
2. User marks a word, opens the vocabulary filter, and sees the same `Menu`/`MenuItem` pattern as every other choice list in the product; the active filter row is `primary-subtle` + accent text — the one list-selected recipe — while the selected study-mode card carries the one card-selected ring (N1, N3).
3. User trips an AnkiConnect failure and reads it once, at the level it blocks, with its recovery path (N10); the card-creator footer presents one primary action, one secondary recipe, and a destructive that looks destructive — nothing enabled wears the disabled costume (N5).
4. User opens an empty Vocabulary or Playlist tab and meets the same `EmptyState` anatomy as every sibling (N7); sidebar groups are separated by hairline dividers and the dictionary↔card-creator seam is a single 1px line (N6).
5. User scans Settings: headings speak the token type scale, `Sync now` reads as the live secondary action it is, slider tracks show their full range, hints read as buttons, and the collapsed header overflows tools into a menu instead of an icon landfill (N8, N9, N11) — landing the promised value: one visual grammar learned once, applied everywhere, on any device.

## Stories

Business-level only — "I want X so that Y, done when Z." Story ≠ task.

- S1: As a panel user, I want "selected" to look the same everywhere so that I always know what's active — done when only the two sanctioned recipes remain across lists and cards.
- S2: As a panel user on any page background, I want floating layers to be opaque and the panel itself clearly above the page so that I can read every menu — done when no floating surface lets content bleed through and the panel carries `shadow-modal` + border.
- S3: As a panel user, I want every choice list to behave like the product's menus so that I can predict interaction — done when vocab filter/sort, tools rows, and the profile switcher all use `Menu`/`MenuItem`.
- S4: As a panel user, I want to tell enabled-secondary from disabled at a glance so that I never skip a live action — done when `Sync now`, `Update`, and destructive actions carry unambiguous emphasis recipes.
- S5: As a panel user, I want structure shown by dividers and labels rather than gaps so that I understand grouping — done when sidebar sections and pane seams use single hairlines.
- S6: As a panel user, I want empty tabs to feel designed so that the product feels finished — done when every tab routes through the shared `EmptyState` anatomy.
- S7: As a maintainer, I want one implementation per recurring visual job so that future features can't drift — done when the status chip exists once, opacity-as-color is gone, and radius/shadow follow the card scale.
