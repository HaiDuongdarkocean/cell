# YouTube PO Token + SW 403 → MAIN world ANDROID client fetch

> **Principles**:
> - [Ephemeral runtime auth token → alternative client without token](principles.md#ephemeral-runtime-auth-token--alternative-client-without-token)
> - [Extension SW lacks page context → MAIN world fetch](principles.md#extension-sw-lacks-page-context--main-world-fetch)

## Problem

YouTube subtitle detection (commit 63fb94d) detected 0 subtitles on every YouTube video. Browser verify on `YQHsXMglC9A` (Adele - Hello) showed:

1. **PO Token blocker**: WEB client `ytInitialPlayerResponse` caption tracks ALL had `exp=xpe` in baseUrl `exp` param (PO Token required, ephemeral single-use). Fetching VTT without PO Token returned `200 OK` with 0 bytes (empty body). `mapYouTubeCaptionTracks` skipped all tracks (PO Token indicator filter) → 0 subtitles.

2. **SW 403 blocker**: Background service worker `fetch()` to `https://www.youtube.com/youtubei/v1/player` returned `403 Forbidden`. SW has no YouTube cookies (cross-origin, no `credentials: include` context) and no page origin → YouTube rejects.

## Root causes

**Bug 1 — PO Token (WEB client)**:
- `src/features/detection/logic/youtubeInnertube.ts` used WEB InnerTube client (`clientName: 'WEB'`).
- YouTube added PO Token requirement (`exp=xpe`) to ALL WEB client caption tracks (2024-2025 anti-bot measure).
- PO Token is ephemeral: generated by YouTube player runtime, single-use, expires in seconds. Cannot be reused or fetched out-of-context.
- Source: yt-dlp issue #13654, Stack Overflow #79668836.

**Bug 2 — SW 403 (page context)**:
- `src/entrypoints/background/handlers/youtubeDetection.ts` fetched InnerTube from background SW.
- MV3 SW `fetch()` runs in extension origin (`chrome-extension://...`), NOT page origin (`https://www.youtube.com`).
- SW has no access to YouTube cookies (SAPISID, HSID, etc.) — cross-origin cookie isolation.
- YouTube InnerTube API requires cookies + origin → SW fetch 403.

## Fix

**M3 — ANDROID InnerTube client** (`youtubeInnertube.ts`):
- Changed `clientName: 'WEB'` → `clientName: 'ANDROID'`, `clientVersion: '20.10.38'`.
- ANDROID client caption tracks have `exp=null` (NO PO Token required).
- Added `visitorData` param (from `ytcfg.get('INNERTUBE_CONTEXT').client.visitorData`) — ANDROID client requires it for session continuity.
- ANDROID client works WITHOUT User-Agent override (empirically verified — API accepts browser's default UA).

**M4 — MAIN world fetch** (`youtube-main-world.iife.ts`):
- Moved InnerTube `fetch()` from background SW → MAIN world content script.
- MAIN world runs in page context (`https://www.youtube.com`) → has YouTube cookies + origin.
- MAIN world fetches ANDROID InnerTube → postMessage `__YT_DETECTED_SUBTITLES` → ISOLATED content-script relays to background → auto-load.

**Architecture flow (revised)**:
```
MAIN world (page context, has cookies+origin)
  → fetch ANDROID InnerTube /youtubei/v1/player
  → parse captionTracks (exp=null, no PO Token)
  → postMessage __YT_DETECTED_SUBTITLES
ISOLATED content-script (listener)
  → relay to background via chrome.runtime.sendMessage
Background SW
  → mapYouTubeCaptionTracks → DETECTED_SUBTITLES → auto-load
```

## Key insight

Two independent blockers (PO Token + SW 403) shared one architectural fix: move the fetch to the MAIN world content script using an alternative InnerTube client. The MAIN world has page context (cookies + origin) that the SW lacks, AND the ANDROID client doesn't require the ephemeral PO Token that the WEB client demands. The original G3 design (ADR-020) rejected ANDROID client ("User-Agent is forbidden header") and SW fetch ("no User-Agent restriction") — both assumptions were empirically wrong: ANDROID client works without UA override, and SW fetch 403s regardless of UA (the blocker is cookies/origin, not UA).
