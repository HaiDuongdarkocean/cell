# Spec Review: Netflix Subtitle Detection

> **Model**: Opus 4.8
> **Date**: 2026-07-13

> **Intent**: MISSING — intent derived from conversation (spec line 6: "conversation 2026-07-13 (Anh yêu yêu cầu tải subtitle netflix.com, ổn định + hiệu năng + thời gian + UX tốt nhất)")
> **Mockups**: NA — Netflix detection is backend logic, no UI mockup referenced
> **Reviewer**: spec-reviewer skill (subagent)

## Status

**APPROVED_WITH_CONDITIONS**

The spec is technically sound and reuses the proven ADR-020/ADR-028 MAIN-world pattern with clear 4-path architecture. However, 3 CRITICAL risks (TTML format unsupported end-to-end, `DetectedSubtitlesPayload.source`/`movieId` not yet in code, ADR-029 handshake source-check bug) and several HIGH risks must be fixed before G4 implementation. The spec itself is well-written; most issues are spec↔code contract drift that the spec/ADR assume-but-don't-yet-exist in the codebase.
