# Spec Review — debug-seam-hardening

3 independent reviews + orchestrator verification against `src/` (~35 file:line citations checked — spec's code claims are accurate: `subtitleBridges.ts:44-64/136-153`, `discoverySchemas.ts:77-95`, `subtitleResponseCache.ts:16-21`, all REQ-3 `'*'` sites, `regionSelector.ts:85,412-413` functional classification, `debugLog.ts:6` + `chrome-apis` import, `vite.config.ts:205` global define, `findIframeBySource`/`postToIframe`/`hasIframeWithOrigin` claims). Traceability vs intent is near-clean (N1–N5 → REQ → AC; intent Out honored). Defects are completeness + one unpassable AC, not wrong evidence.

Blockers:
1. [Success Criteria AC-5 / REQ-5 Postcondition] [PO/TL]: AC-5 asserts "post forged **valid-shape** + malformed signals → cache unchanged" — but a schema-valid forged signal from a hostile frame WILL pass `subtitleDiscoveryBridgePayloadSchema` (its `event.origin` is real; nonce is shape-only per the spec's own Rules) and reach `cacheSubtitleBody`; the spec's Open Questions admits exactly this. The AC cannot pass as written; REQ-5 Postcondition ("forged/malformed signals cannot reach the cache") overstates identically. Fix: reword to "malformed/schema-invalid/missing-nonce signals are dropped before `cacheSubtitleBody`; well-formed signals are re-origined via `event.origin` and accepted — residual well-formed forgery bounded to per-frame in-memory cache (accepted risk)".
2. [REQ-5 / AC-5] [TL]: Wire-`nonce` sender inventory missing — the primary discovery channel dies. Envelope validation requires `nonce ≥16` on the wire and AC-5 extends it to the same-window path, but NO current sender emits a nonce: `subtitleDiscovery-main-world.iife.ts:91` (same-window) + `:101` (parent), `fetchInterceptor.iife.ts:201,252` — the last is the main `network-response` producer. The spec's cite "same-window path already does this at :141-143" is `subtitleBridges`' RECEIVER-side generation for the background payload, not a sender. Also `crypto.randomUUID()` is secure-context-only → `undefined` on `http:` embed pages → needs the `${Date.now()}-${rand}` fallback (pattern at `subtitleBridges.ts:141-143`). Fix: either enumerate all send sites as needing a wire nonce (with fallback), or exempt the same-window path from the wire-nonce field while still schema-validating `signal` (bridge keeps generating the forwarded nonce) — pick one explicitly.

Major:
1. [REQ-3 Preconditions / AC-3 / REQ-4 / NFR-2] [TL]: `mediaScan.ts:46-53` `__CELL_DEBUG_PAGE_SCAN` posts `pageUrl: location.href` + media inventory to `window.parent` with `'*'` — a cross-frame `'*'` send missing from REQ-3's inventory and AC-3's file list, contradicting REQ-3's Goal and NFR-2 "grep-clean". `__CELL_AUTOLOAD_HANDLED` (`contentScriptMessages.ts:184`) likewise keeps `href: location.href` — violates REQ-4's "no `location.href` value leaves a frame boundary" and AC-4 as literally written. Fix: add mediaScan's send to REQ-3 (referrer-origin) and either minimize `pageUrl`/`href` or write an explicit "debug-gated sends exempt" rule into REQ-3/REQ-4/NFR-2 + scope AC-4 to production paths.
2. [REQ-3 / REQ-4 / REQ-5 / Open Questions] [TL]: Opaque/'null'-origin + iframe-src edge cases unhandled. (a) `event.origin === 'null'` (sandboxed/opaque frame) → forwarded `origin` fails `originSchema` (`discoverySchemas.ts:15-25`) → legit signal dropped — record the behavior. (b) `iframe.src` empty/`about:blank`/`srcdoc` → `new URL` throws or yields `'null'`; `postMessage(msg,'null')` throws — define "resolvable origin" = valid http(s) origin, else skip. (c) Top-initiated PM/MGR notify (`notifyChildByIframe` `iframePlayerModeBridge.ts:191-199`, `postToIframe`) silently dies on src-less iframes — regression vs `'*'` today, unrecorded. (d) The empty-referrer Open Question covers only the discovery relay — the same condition kills functional PM/MGR child→top posts; intent Risk row 5 named about:blank/blob/re-navigated iframes and the spec dropped them. (e) REQ-4 `frameSrc = location.origin + location.pathname` yields garbage for non-http(s) docs (`'null' + '/blank'`) → `findIframeBySource` fails. (f) REQ-4 Exception mechanism is wrong: an opaque origin does NOT throw — `location.origin` returns `'null'`; `''` occurs only on real throws. Fix: rules for (a)(b)(e)(f) + Open Questions entries for (c)(d).
3. [REQ-3 Basic flow / Flows "Origin resolution"] [TL]: `document.referrer` chosen with no alternatives analysis — and it breaks after intra-iframe self-navigation: `referrer` becomes the iframe's own previous URL → `new URL(document.referrer).origin` = child origin ≠ parent → every child→parent post (discovery relay, PM ENTER/EXIT, all `MGR_*`) silently drops. `location.ancestorOrigins?.[0]` returns the direct parent's origin browser-enforced and survives self-navigation. Fix: resolve via `location.ancestorOrigins?.[0]` with `document.referrer` as fallback — or document why referrer was chosen (TL lens requires ≥2 alternatives examined).
4. [REQ-5 scope / REQ-6] [TL]: Inbound-validation asymmetry on sibling channels — unrecorded. `installIframePlayerModeBridge` (`iframePlayerModeBridge.ts:228-243`) accepts `__CELL_PLAYER_MODE_ENTER/EXIT` from any window trusting self-reported `frameSrc` → a hostile embedded frame can trigger fullscreen, or the no-gesture fallback mounts a `z-index:2147483647` fixed overlay on a chosen host — phishing-grade UI takeover. `hasIframeWithOrigin(e.origin)` (`iframeManagerBridgeHost.ts:72`) passes for ANY embedded iframe → forged `MGR_OPEN` renders attacker `state` on the host sheet. All child-side listeners (`iframePlayerModeBridge.ts:296-303`, `subtitlePlayerMode.ts:29-38`, `iframeManagerBridgeChild.ts:19-26,72-90`) accept any post — same threat model REQ-5 fixes for discovery. Fix: bind inbound checks (`e.source === resolvedIframe.contentWindow` for PM; `e.origin === new URL(frameSrc).origin` for MGR child posts) or record an explicit accepted-risk entry in Open Questions.
5. [REQ-4 / Data / NFR-2] [TL/BA]: `apiKeys` cross the boundary — real user OpenSubtitles credentials serialized into `SerializedManagerState` (`managerStateSerializer.ts:33`, `iframeManagerBridgeTypes.ts:38`) and posted `MGR_OPEN`/`MGR_STATE` child→top. Explicit targetOrigin does not hide the payload: the destination IS the embedder window whose page scripts can `addEventListener('message')`. `apiKeysChange` actions mirror keys top→child into the player frame. The Data table reduces bridge payloads to "`MGR_*` + `frameSrc`" — credential fields unanalyzed. Fix: redact `apiKeys` from bridge-serialized state (host loads keys via `chrome.storage` itself) or record residual exposure honestly in Open Questions + NFR-2.
6. [REQ-5 Basic flow steps 2→3] [TL]: Validate-then-override ordering makes the `event.origin` override useless for `player-state`: the envelope parse already rejects non-http(s) self-reported `signal.origin` (`originSchema`) before step 3 can repair it, and `event.origin === 'null'` fails the forwarded-payload schema anyway. Fix: specify "validate signal shape → set origin/initiator from `event.origin` → re-check", and state the `event.origin === 'null'` decision (drop — consistent with fail-closed).

Minor:

Qualify paths.
6. [Open Questions line 213] [BA]: garbled merged bullet — two thoughts fused mid-word; split.

Gating them remains correct hygiene (N5), but the "shared DOM/globals" framing is partly inaccurate.

## Applied fixes

All 9 action items applied to `docs/specs/debug-seam-hardening.md`:

1. AC-5 + REQ-5 Postcondition reworded to the real guarantee (malformed/invalid dropped before cache; well-formed accepted with `event.origin`; residual bounded forgery = accepted risk).
2. Wire-nonce decision made explicit: NO wire nonce anywhere (senders don't emit; trivially spoofable); receiver generates forwarded nonce uniformly; `subtitleSignalSchema` is the inbound validator, not `subtitleDiscoveryBridgePayloadSchema`; insecure-context `randomUUID` fallback noted.
3. `mediaScan.ts:47` added to REQ-3 inventory + AC-3; debug-gated sends exempted from REQ-4 minimization (E2E asserts on `href`/`pageUrl`); `__CELL_AUTOLOAD_HANDLED` mis-target recorded.
4. Resolvable-origin = http(s) defined; `'null'`/`about:blank`/`srcdoc`/re-navigated behavior recorded in REQ-3 Exception + Open Questions; REQ-4 Exception fixed (opaque origin → `'null'`, not throw; send skipped by REQ-3 anyway).
5. Child→parent resolution switched to `location.ancestorOrigins?.[0]` with `document.referrer` fallback (survives intra-iframe self-navigation).
6. New REQ-7: inbound `e.source`/`e.origin` checks for PM/MGR channels (forged `MGR_OPEN`/ENTER fullscreen-hijack closed; child-side listeners bound to resolved parent origin) + AC-8.
7. `apiKeys` residual exposure recorded in REQ-4 Rules, Data table, NFR-2, Open Questions (redaction = Manager Sheet UX change → follow-up).
8. REQ-5 ordering fixed: `'null'`/non-http(s) origin drop → signal schema validate → override origin/initiator from `event.origin` → re-check → cache/relay.
9. Minors: AC-1 functional-attr carve-out; AC-7/AS-IS-1/REQ-7 traceability rows; REQ-6 template fields filled + feature-map orphan resolved; REQ-2 inventory + `__*_DEBUG` publish-only note + missing declares; paths qualified (`src/features/subtitle/ui/`, `src/features/ocr/pipeline/`); isolated-world vs page-observable framing corrected in REQ-1 Goal; same-window blast-radius wording fixed; `ocrContentScript.ts:901` + already-gated `:186-449` added.
