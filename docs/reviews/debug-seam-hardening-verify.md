## New defects / regressions found

None that violate the spec. Notable behavior changes observed (all bounded):

1. **Top-frame `data-cell-autoload-handled` no longer emitted in debug builds.** `contentScriptMessages.ts:178-192` now targets `resolveParentFrameOrigin()`; in the top frame that resolves to `document.referrer` origin or `undefined`, so the self-post never delivers (previously `targetOrigin=location.origin` self-delivered via `window.parent===window`). The marker's documented purpose is iframe→top acknowledgment; no E2E asserts the top-frame variant. Minor observability loss, arguably spec-conforming ("delivers where intended").
2. **Same-origin iframes now double-forward discovery signals** — the iframe's own CS forwards the same-window post AND the top CS now forwards the parent post (previously dead on missing nonce). Bounded: background pipeline dedupes by URL; consistent with the repair-the-relay goal.
3. **MGR host tolerates missing/non-string `frameSrc`** — corroboration only runs `if (typeof frameSrc === 'string')` (`iframeManagerBridgeHost.ts:86-91`). A `frameSrc`-less `MGR_OPEN` still renders the sheet (actions then can't route back — `new URL(undefined)` throws, caught). Legit senders always send it; minor looseness vs strict corroboration.
4. **`installHostManagerSheet()` installs the MGR listener in every frame** (`content-script.ts:48`, unconditional) — a nested grandchild iframe can open a sheet inside its parent frame. Consistent with the bridge's any-level design.
5. **Perf nit**: `isIframeContentWindow`/`hasIframeWithOrigin` run `querySelectorAll('iframe')` per message event on the top window — same cost class as the pre-existing `hasIframeWithOrigin`; acceptable.
6. Docs nit: `docs/2-architechture-system.md` table should name `isIframeContentWindow` alongside the other `frameOrigin` helpers (consumer rows do describe the inbound checks at :61,:213). — **fixed post-review**.

## Residual risks (accepted or needs follow-up)

1. **Self-elevation remains possible (needs follow-up).** REQ-7's mechanism verifies the sender is *an* iframe on the page — it cannot distinguish a hostile ad iframe from the legit player iframe. A hostile embedded iframe posting `__CELL_PLAYER_MODE_ENTER` with its own `frameSrc` passes all checks and triggers the `data-cell-player-mode-host` fallback (`position:fixed;inset:0;z-index:2147483647`) on itself/its container — a full-viewport overlay on the host page — or `MGR_OPEN` rendering attacker-controlled `state` on the host sheet. The hardening blocks non-iframe sources and cross-identity forgery only. Inherent to the spec's chosen check ("legitimate player iframes pass because they ARE iframes on the page") — follow-up could restrict to video-hosting/largest iframes or require a prior discovery handshake.
2. **No session binding (needs follow-up).** Once PM/MGR is active for iframe A, any other embedded iframe B can post `EXIT`/`MGR_STATE`/`MGR_CLOSED` and tear down or mutate A's session (checks verify only that the sender is *some* iframe). Follow-up: record `e.source` at OPEN/ENTER and require subsequent control messages from the same window.
3. **Embedder-page spoofing on the child side.** Embedder page scripts share `parentOrigin`, so they can post `MGR_ACTION` (incl. `apiKeysChange` → persists keys via `handleApiKeysChange` → `saveSettings`), `MGR_CLOSE`, `ENTERED`/`EXITED` into the child iframe and pass the origin check. Inherent — the extension's own replies are indistinguishable from page-script posts on the same origin; only a non-postMessage channel (spec non-goal) fixes it. Exposure window is bounded to when the manager sheet is host-delegated (`managerOpenOnHost`).
4. **`apiKeys` credentials still cross the bridge** in `MGR_OPEN`/`MGR_STATE`/`apiKeysChange` — visible to embedder page scripts listening on the top window. Recorded in spec Open Questions; unchanged.
5. **`data.state` in `MGR_OPEN` is unvalidated** — cast to `SerializedManagerState`; attacker-controlled sheet content renders (React text-escapes → no HTML injection; display-only, actions operate on the child's own state). Bounded UI spoofing.
6. **Debug-only looseness**: `installDebugFrameMessageListener` accepts `__CELL_AUTOLOAD_HANDLED` from any source without an origin check (`debugLog.ts:28-33`) — debug builds only, production emits nothing.
7. Previously recorded accepted risks still stand: empty `ancestorOrigins`/`referrer` → fail closed; src-less/`about:blank`/`srcdoc`/re-navigated iframes break top-initiated notify; well-formed forged discovery signals bounded to per-frame cache; same-window forgery = same trust domain.
