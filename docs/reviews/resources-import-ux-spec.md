# Spec Review — resources-import-ux

Spec: `docs/specs/resources-import-ux.md` · Intent: `docs/intent/resources-import-ux.md` · Lenses: BA / PO / TL (3 independent reviews, merged). Code claims spot-verified by orchestrator (`batchProcessor.ts:39` emits `onProgress(processed)` only; `total` already plumbed end-to-end as spec states).

Blockers:
1. [REQ-7 / Function↔Feature map] [TL]: Reusing `DictionaryPanelView` from `features/dictionary` creates a new feature cycle → `npm run build` fails. `dictionaryPopup` already imports `features/dictionary` in production code (`useDictionaryLookup.ts:13`, `CandidateView.tsx:12`, `lookupOrchestrator.ts:28-38`); `KNOWN_CYCLES` in `check-feature-cycles.mjs:37` is empty → `ResourcesPanel.tsx` importing `@/features/dictionaryPopup/ui/DictionaryPanelView` closes a `dictionary↔dictionaryPopup` cycle and fails prebuild. Compounding: `dictionaryPopup` has no `index.ts` barrel → any cross-feature import is a deep import → `check-deep-imports.mjs` ratchet fails. DoD `npm run build` cannot go green as specified. Fix: spec must name the seam — compose the lookup column at `settings`/`universalPanel` feature level (acyclic: `dictionaryPopup` does not import them), expose the integrated view via a new `dictionaryPopup/index.ts` barrel, and reuse the existing `Dictionary` wrapper (`Dictionary.tsx:122-124` already renders `variant='integrated'`, same as `DictionaryTab.tsx:75-88`).

Major:
1. [REQ-3 / REQ-5] [BA+TL+PO]: Duplicate-signature race introduced by parallelism is unspecified and corruption-adjacent. Client check `listResources().find(signature)` (`resourceClient.ts:150-151`) and SW check `findResourceBySignature` (`importOrchestrator.ts:60`) both pass concurrently when two same-signature files land in one batch (or when a resource is created between check and upload) → `skippedAsDuplicate` arrives with no prompt, and `decision==='replace'` cascade-deletes a resource that may be a sibling job's still-importing `installationFinished=false` record (`importOrchestrator.ts:73`); the sibling's finalize then no-ops and reports success for a deleted resource. Today's UI also offers "Thay thế" re-run on result-shaped skips (`ResourcesPanel.tsx:330-335`) — spec's `skipped` terminal state has no outgoing edge → silent regression. Fix: rules for (a) enqueue-time signature dedupe across queued/running jobs; (b) replace must never target `installationFinished=false` resources (defer/block); (c) decide whether skipped rows expose a replace affordance (parity with today).
2. [REQ-3 / NFR-1] [TL+BA]: Memory model understates real peak ~4-5×. Panel side: `readAsDataUrl` holds a ~213MB base64 string per uploading job for the whole upload loop (`resourceClient.ts:181-183`). SW side: `pendingImports` accumulates ~213MB of chunks; decode spike adds `chunks.join('')` + `atob` binary + `Uint8Array` + `File`/`ArrayBuffer` ≈ ~700MB transient for ONE 160MB job (`resources.ts:185-196`, `importOrchestrator.ts:77`). Two overlapping jobs (A decoding + B uploading) ≈ ~900MB+ SW — OOM on the 1GB persona is plausible even at cap=2. Fix: rewrite NFR-1 and REQ-3 cap rationale in peak-bytes terms (base64 resident in renderer AND SW + decode spike), or bound by total in-flight bytes; keep the real-hardware verification item.
3. [REQ-3 Goal / NFR-3 / SC-3] [TL+PO+BA]: "finishes in roughly the time of its slowest members" is unachievable — the MV3 SW is single-threaded; `base64ToBytes` (~160M-iteration sync loop, `resources.ts:77-82`), `JSON.parse`, `gunzipFile`, `unzipAll` only interleave at IDB awaits. Real speedup = bounded overlap of IDB waits; sibling progress stalls during a sync parse burst. NFR-3 "materially faster" is a non-measurable red-flag term; SC-3 units inconsistent ("large-file" vs NFR-1's "6 × 160MB"). Internal contradiction: `:58` "FIFO per section" vs `:60` "queue is shared". Fix: reword Goal to bounded-overlap under the cap; give NFR-3/SC-3 a measurable target on a defined fixture (e.g. 6 × 160MB ≈ ceil(N/2) waves); pick global FIFO.
4. [REQ-2 Rules] [BA+TL]: Per-format total contract partially wrong vs actual strategies. (a) `json-array` does NOT materialize a parsed array — it regex-streams strings (`jsonArrayStrategy.ts:54-69`) → needs a count pass or honest indeterminate. (b) term-bank FREQUENCY yields only `type==='freq'` rows (`termBankStrategy.ts:131`) → "sum of entry counts across bank files" over-counts vs the spec's own postcondition; count pass must apply the mode filter. (c) sqlite frequency path falls back `langFrequencyEntry → entries` (`sqliteStrategy.ts:124-131`) → `COUNT(*)` must mirror the actual table. (d) term-bank baseline misdescribed: `unzipAll` already inflates ALL banks up front (`termBankStrategy.ts:52-54`) — today's peak is all-banks-decompressed, not "single-bank profile". Fix: reword rules to mechanism-accurate statements; keep the postcondition (denominator = attempted entries) as the invariant.
5. [REQ-7 Rules] [BA+TL]: "card-creator actions omitted — results are read-only verification" is unachievable as written AND contradicts the locked "same fidelity as the video popup" decision. Send-to-card renders unconditionally in `CandidateView` (`CandidateView.tsx:156-167`; only quickAdd is prop-gated) and silently no-ops without the callback (`useCandidate.ts:207-208`) → dead button. Status pill cycles and persists via `setWordStatus` unconditionally (`useCandidate.ts:180-185`); search history writes session storage; media toolbar active with `preloadMedia=true`. Fix: reword to match the full-fidelity decision; specify send-to-card gating (requires touching `CandidateView`); state whether status cycling/history writes are acceptable.
6. [REQ-1 postcondition / REQ-5] [BA+TL]: Parked duplicate prompt violates "exactly one terminal outcome" and can starve the queue. An unanswered prompt is a never-resolving promise holding one of 2 concurrency slots — spec doesn't say whether a pending prompt occupies a slot (queue can stall indefinitely). Unmount claim overstates: "jobs continue in SW if unmounted" only holds post-upload — mid-upload unmount leaks a partial `pendingImports` entry (~213MB until 10-min TTL, `resources.ts:45,176-178`); queued jobs' `File` objects live panel-side, so tab close kills everything. Fix: specify prompt-abandonment/slot-occupancy rules; scope the unmount claim (dialog close vs page unload); record SW-termination mid-parse as accepted risk or add lost-contact error.

Minor:
1. [REQ-2 Actor] [BA]: `Background SW` listed as actor (table + REQ-2) — SW is system-internal; actor should be User (viewer), emission under system steps.
2. [REQ-1 Exception] [BA]: "Validation failure → row flips straight to error" overstates — validation runs SW-side AFTER all chunks upload (`resources.ts:192-197`); drag-drop bypasses `accept` (`Dropzone.tsx:30-36`). A >500MB file uploads ~1.33× its size first. Fix: client-side size/extension pre-check at enqueue (`file.size` is free) or soften wording.
3. [REQ-1/Data] [BA]: jobId ownership unspecified — `jobId` is minted inside `importResourceFile` (`resourceClient.ts:169`) and never returned; "rows keyed by a client-generated job id" implies a contract change. State it.
4. [REQ-7] [BA+TL]: No lookup timeout (`useDictionaryLookup.ts:193-216` has none → stalled SW spins forever); mid-import `installationFinished=false` resources are NOT filtered from lookups (`lookupOrchestrator.ts:188-194`) → partially-imported dicts answer queries — NFR-6 should state intent.
5. [Traceability] [PO+BA]: Showcase mock parity is intent Scope-In + DoD line but has no REQ/Function-map row — orphaned requirement (`mockDictionary.ts:351-357` resolves chunks instantly, no progress pushes). Fix: add rule under REQ-1 + traceability row.
6. [REQ-7] [TL+BA]: Shadow DOM — settings mounts via `mountReactShadow`; `document.getElementById(SEARCH_INPUT_ID)` autofocus (`DictionaryPanelView.tsx:192-207`) can't cross shadow boundary (dead autofocus, parity with DictionaryTab); fixed id `dictionary-panel-search-input` can collide with a coexisting integrated panel.
7. [SC-1 vs lifecycle diagram] [PO]: SC-1 lists `queued → uploading → importing → terminal`; diagram adds `counting/parsing` + `duplicate-prompt`/`skipped` terminals. Align.
8. [REQ-1/REQ-6/REQ-7 wording] [PO+BA+TL]: "job rows live above/beside the resource list" — pin placement; SC-7 "persists after refresh" — say panel-remount vs reload; REQ-2 exception should note it's unreachable for enumerated formats (defensive-only); no MoSCoW ordering (optional one-liner).
9. [REQ-5 refresh] [TL]: `refresh()` toggles `loading` → skeleton flash (`ResourcesPanel.tsx:260-274`) — per-completion refresh must specify a non-skeleton path.
10. [Boundaries] [TL]: No grip icon in `ICON_CATALOG` — only `move`/`moveVertical`/`moveHorizontal` (`icons/index.ts:313-315`); spec should name `moveVertical` or allow adding one SVG.

## Applied fixes

Post-review revision of `docs/specs/resources-import-ux.md`:

- **Blocker (REQ-7 seam):** spec now binds composition to the `settings` level — `SettingsDialogContent` Resources card hosts the two columns; new `dictionaryPopup/index.ts` barrel exporting `Dictionary`; explicit rule forbidding `features/dictionary` → `features/dictionaryPopup` (KNOWN_CYCLES stays empty). Boundaries updated.
- **Major 1 (duplicate race):** REQ-3 rule adds enqueue-time signature dedupe across queued/running jobs (skipped row consumes no slot); REQ-5 adds the replace guard — replace refused when the existing resource has `installationFinished=false` (UI affordance + SW-side rejection); skipped rows keep the "Thay thế" re-run affordance.
- **Major 2 (memory model):** NFR-1 + REQ-3 rewritten in peak-bytes terms (~1.33× resident chunks + ~4× decode spike per job, renderer-side base64 noted); dual bound `MAX_CONCURRENT_IMPORTS=2` + `MAX_INFLIGHT_BYTES≈256MB`.
- **Major 3 (parallel overpromise):** Goal reworded to bounded overlap on the single-threaded SW; global FIFO replaces the contradictory per-section note; NFR-3/SC-3 now target a measurable ≥20% wall-time reduction on the defined 6 × ~160MB fixture.
- **Major 4 (per-format totals):** REQ-2 rules corrected — json-array regex count pass, term-bank mode filter + corrected all-banks-decompressed baseline, sqlite fallback-table COUNT(*), json-entries/wordlist parsed-length.
- **Major 5 (REQ-7 fidelity):** "read-only" claim removed; send-to-card gating on callback presence specified (CandidateView/useCandidate change); status-cycling + history writes declared acceptable.
- **Major 6 (parked prompts/unmount):** slot-occupancy rule (parked prompt holds its slot, queue flows through the other); unmount claim scoped (post-upload continues, mid-upload TTL-reaped, queued die); SW-termination added to Open Questions.
- **Minors:** REQ-2 actor corrected to User; client-side pre-validation rule added; `options.jobId` contract stated; `installationFinished=false` exclusion from lookups added to REQ-7/NFR-6; mock-parity promoted to REQ-1 rule + SC-9 + traceability row + function-map row; shadow-DOM autofocus/id-collision recorded in Open Questions; SC-1 aligned with lifecycle diagram; job-row placement pinned (above resource cards, inside the section); SC-7 says remount+reload; MoSCoW line added; soft-refresh rule kills the skeleton flash; `moveVertical` named as the grip icon.

VERDICT: APPROVE_WITH_CHANGES
